---

## 1. 目的

現在は取得した記事の `excerpt`（抜粋）をそのまま表示しているが、これを Gemini API を通して要約することで、記事の内容をより効率的に把握できるようにする。

### 着手の理由

- M2 完了時点で基本機能は揃ったが、抜粋だけでは記事の価値を判断しにくい
- Gemini 3.5 Flash は低コストで品質も十分（入力 $0.075/1M tokens、出力 $0.30/1M tokens）
- 手動で Gemini に貼り付ける運用を自動化し、UX を改善したい

## 3. アーキテクチャ設計

### 3.1. データモデルの拡張

```python
# models.py
class ScoredItem(BaseModel):
    item: Item
    score: float
    score_breakdown: dict[str, float] = Field(default_factory=dict)
    summary: str | None = None  # 新規追加
```

### 3.2. Summarizer 抽象化

```python
# summarizer/base.py
class SummarizerAdapter(Protocol):
    def summarize(self, item: Item) -> str | None:
        """記事を要約。失敗時は None を返す。"""
        ...
```

スコアリングと同様に契約ベースで隔離し、将来的に他の LLM への切り替えを容易にする。

### 3.3. パイプライン統合ポイント

```
fetch (sources) → score (scorers) → summarize (summarizer) → store
```

要約は取得時に一度だけ実行し、結果を `run_store` に保存する。

### 3.4. 設定ファイル構造

```toml
[summarizer]
enabled = false  # デフォルトは無効（API キー設定が必要）
provider = "gemini"
model = "gemini-3.5-flash"
api_key_env = "GEMINI_API_KEY"
max_output_tokens = 200
temperature = 0.3
```

### 3.5. エラーハンドリング

- API 呼び出し失敗 → `summary = None` で継続（記事表示は壊さない）
- API キー未設定で `enabled = true` → 起動時に警告ログ、要約スキップ
- レート制限エラー → 簡易リトライ（exponential backoff）

## 4. 受け入れシナリオ

### シナリオ 1: 要約機能オフ（デフォルト）

1. `config.local.toml` で `[summarizer] enabled = false`（またはセクションなし）
2. `my-feed serve` で起動
3. 「いま取得」→ 記事一覧に要約が表示されない
4. Markdown DL しても要約セクションなし

### シナリオ 2: 要約機能オン

1. `export GEMINI_API_KEY="your-api-key"`
2. `config.local.toml` で `[summarizer] enabled = true`
3. `my-feed serve` で起動
4. 「いま取得」→ 記事一覧に「AI 要約」が表示される
5. Markdown DL すると「### AI 要約」セクションが含まれる
6. 履歴から過去の実行を開いても要約が表示される

### シナリオ 3: API エラー時の継続性

1. 要約機能をオンにして、無効な API キーを設定
2. 「いま取得」→ 要約は生成されないが、記事一覧は正常に表示
3. ログに警告が出る

## 7. 技術選定の理由

### なぜ Gemini 3.5 Flash か

- **コスト**: 入力 $0.075/1M tokens、出力 $0.30/1M tokens（GPT-4 Turbo より安価）
- **品質**: 要約タスクには十分な性能
- **レート制限**: 無料枠でも 15 RPM（Requests Per Minute）利用可能
- **SDK**: 公式 Python SDK が使いやすい

### なぜパイプライン統合か

- 取得時に一度だけ要約を生成し、ストレージに保存
- 同じ記事を何度も見ても追加コストなし
- オフライン動作も可能（一度要約を生成すれば）

---

## 8. 想定コスト

### トークン見積もり

- 1 記事あたりの入力: 約 500 トークン（`excerpt` + メタデータ）
- 1 記事あたりの出力: 約 150 トークン（要約 3-4 行）

### 料金計算

- 入力: 500 tokens × $0.075/1M = $0.0000375
- 出力: 150 tokens × $0.30/1M = $0.000045
- **合計: 約 $0.00008/記事**

10 記事で約 $0.0008（約 0.1 円）なので、日常的な使用でもコストは無視できるレベル。
