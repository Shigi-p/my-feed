# M3 — 運用改善

| 項目 | 内容 |
|------|------|
| 依存 | **M2** をしばらく使ってからの着手を推奨 |
| 後続 | M4（任意） |
| ゴール | ソースや評価基準の変更が、コード大改修なしで試せる |

---

## 1. 目的

実運用の摩擦を下げる。  
Adapter / Strategy / config の境界を、運用者向けに露出する。

---

## 2. スコープ

### やること（優先度順）

1. ソース有効/無効を設定（可能なら UI）で切替
2. 件数・減衰パラメータ等の設定化
3. 取得失敗の可視化強化（CLI/Web 揃え）
4. ソース追加・スコアラー追加ガイド（`docs/guides/` 推奨）
5. GIGAZINE 等の任意フィルタを **設定口だけ**用意（デフォルトオフ）

### やらないこと

- 本番認証・公開（M4）
- LLM 要約本導入（M4）
- Drive（M4）
- 自動学習レコメンド

---

## 3. 設定拡張例

```toml
top_n = 10
default_scorer = "hybrid"

[sources.gigazine]
enabled = true
keyword_filter_enabled = false
keyword_allowlist = []

[scoring.hybrid]
recency_half_life_hours = 36
neutral_popularity_when_missing = 0.5
```

初期はファイルを単一真実にし、UI トグルは後付けでよい。

---

## 4. タスク分解

### T1. 設定の正式化

- [ ] パラメータ集約とバリデーション
- **完了**: コードを触らず top_n / half_life を変更可

### T2. ソース enable

- [ ] 設定反映（任意で Web トグル）

### T3. エラー可視化の揃え

- [ ] Web / CLI
- **完了**: partial が一目で分かる

### T4. ガイド

- [ ] `add-source` / `add-scorer`
- **完了**: 手順どおりダミーを足せる

### T5. フィルタ口（デフォルトオフ）

- [ ] オフ時挙動不変
- **完了**: オン時のみ絞り込み
