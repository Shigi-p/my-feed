# T-Web — Web UI トラック

| 項目 | 内容 |
|------|------|
| 依存 | **C0 必須**。T-Md / T-Store / 実ソースは **Fake で代替可** |
| 合流先 | M2 |
| ゴール | localhost で「いま取得」→ 一覧 → Markdown DL の導線が動く（Fake 可） |

---

## 1. 目的

任意トリガーの主戦場をブラウザに移す UI を、**契約に対して**先に作る。  
実験の中心: C0 完了後、実 Adapter を待たずに着手する。

---

## 2. スコープ

### やること

- FastAPI 最小 UI
- スコアラー選択 + 「いま取得」ボタン
- Top 10 一覧（タイトル・出典・スコア・リンク）
- Markdown DL（最初はスタブ文字列でも可 → T-Md 接続は M2）
- 履歴・お気に入り画面の骨格（Store はメモリ Fake 可）
- `127.0.0.1` バインド前提の起動手順

### やらないこと

- 本番デプロイ・認証
- 実ソース必須の結合（M2）
- 凝ったダッシュボード
- Drive / AI

---

## 3. UI 最小セット

1. アプリ名（my feed）
2. スコアラー選択 + 「いま取得」
3. Top 10 リスト + お気に入りボタン
4. Markdown DL
5. ナビ: 履歴 / お気に入り

装飾より、取得・保存・書き出しが迷わないこと。

---

## 4. ルート案

| メソッド | パス | 説明 |
|----------|------|------|
| GET | `/` | 最新 or 空 + 取得フォーム |
| POST | `/runs` | いま取得 → 保存 → リダイレクト |
| GET | `/runs` | 履歴一覧 |
| GET | `/runs/{id}` | 詳細 |
| GET | `/runs/{id}/markdown` | bundle DL |
| GET | `/runs/{id}/items/{item_id}/markdown` | single DL |
| POST/DELETE/GET | `/favorites` | お気に入り |

初期はサーバサイドレンダリング中心でよい。

---

## 5. Fake で進める約束

```text
POST /runs
  → run_pipeline(config)   # C0 Fake or 後で本番
  → store.save_run(...)    # メモリ実装可
  → render_bundle(...)     # スタブ or T-Md
```

M2 で差し替える箇所をコード上で分かりやすくする（例: ファクトリで注入）。
