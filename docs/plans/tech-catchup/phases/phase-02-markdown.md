# Phase 2 — Markdown と一覧体裁

| 項目 | 内容 |
|------|------|
| ステータス | 計画承認待ち |
| 依存 | Phase 1 完了（`ScoredItem` パイプラインが使える） |
| 後続 | Phase 3（ローカル Web から DL） |
| ゴール | Top 10 を Gemini / ChatGPT に貼って壁打ちできる Markdown をファイル出力できる |

---

## 1. 目的

「リストを見て終わり」ではなく、気になった項目を **壁打ち用プロンプト素材** に変換する。  
AI 要約は使わず、ルールベース抜粋 + 定型テンプレで十分とする。

---

## 2. スコープ

### やること

- 抜粋の整形（1〜3 行）
- 「なぜ今見る価値があるか」一文の生成
- 壁打ち用の問い・アイデア定型ブロック
- **10 件まとめ Markdown**
- **1 件分テンプレ**（単体コピー用）
- CLI からの `.md` 書き出し

### やらないこと

- LLM API 呼び出し
- Google Drive アップロード
- Web UI（Phase 3）。ただし Markdown 生成関数は Web から呼べる純関数にする
- お気に入り永続化

---

## 3. モジュール構成案

```
src/my_feed/
  output/
    __init__.py
    excerpt.py          # ルールベース抜粋
    value_line.py       # 見る価値の一文
    prompts.py          # 壁打ち用問い生成
    markdown_bundle.py  # 10件まとめ
    markdown_single.py  # 1件テンプレ
```

CLI 追加例:

```bash
my-feed run --out-md out/daily.md
my-feed render-md --from result.json --out out/daily.md
my-feed render-md-one --id zenn:xxxxx --from result.json
```

`run` に載せるか、`render-md` を分けるかは実装時判断。  
**推奨**: パイプライン結果 → レンダラ、の二段にして Web 再利用しやすくする。

## 4. 生成コンテンツ仕様

### 4.1 各項目ブロック（必須要素）

ロードマップ合意どおり、各アイテムに含める:

| 要素 | 生成方法（初期） |
|------|------------------|
| タイトル | `item.title` |
| URL | `item.url` |
| 出典 | `item.source` の表示名 |
| 抜粋 | `excerpt.py` で 1〜3 行 |
| タグ | `item.tags`（無ければ省略） |
| 見る価値 | スコア内訳・出典・新しさからテンプレ文 |
| 壁打ちアイデア | 定型の問い 2〜3 個（タイトル/タグを埋め込み） |

### 4.2 抜粋ルール（初期案）

1. `item.excerpt` があれば HTML タグ除去 → 空白正規化
2. 文の区切りで最大 3 文 or 最大 N 文字（日本語 120〜200 目安）
3. 空なら「（抜粋なし）」とし、タイトルのみで壁打ちテンプレを成立させる

### 4.3 「見る価値」一文（初期テンプレ例）

- hybrid: 「{source} で注目度が高く、比較的新しい話題です（score={score:.2f}）。」
- popularity: 「{source} 内で相対的に人気が高い項目です。」
- recency: 「公開が新しく、いま触れておく価値がありそうです。」

完璧な文じゃなくてよい。後で差し替え可能にする。

### 4.4 壁打ちブロック（初期テンプレ例）

```markdown
### 壁打ちの問い
1. この話題を自分の今の課題にどう接続できる？
2. 似た既存ツール/記事との差分は何？
3. 明日試せる最小アクションは？
```

タイトルやタグを使った可変版にしてもよいが、Phase 2 では定型で可。

## 5. Markdown 出力フォーマット

### 5.1 10 件まとめ（`bundle`）

```markdown
# my feed — YYYY-MM-DD HH:mm
- scorer: hybrid
- count: 10

## 1. {title}
- source: ...
- url: ...
- score: ...
- tags: ...

{excerpt}

**なぜ今見るか:** ...

### 壁打ちの問い
...

---
## 2. ...
```

末尾に「まとめて貼る用」短い導入文を付けてもよい:

```markdown
## Gemini への貼り付け導入（任意）
以下は今日の技術キャッチアップ候補10件です。気になるものについて深掘りと学習プランを一緒に考えてください。
```

### 5.2 1 件テンプレ（`single`）

bundle の 1 セクションと同等 + 「この 1 件だけ深掘りしたい」導入文。

## 9. リスク

| リスク | 緩和 |
|--------|------|
| 抜粋がゴミ（HTML 残骸） | タグ除去と長さ上限をテスト |
| テンプレが機械的で使いにくい | 実地で 1 回貼って調整。構造は変えず文言だけ直す |
| Phase 3 と結合しにくい | I/O を純関数に閉じる |
