# Phase 5 — 公開・認証・発展（必要になったら）

| 項目 | 内容 |
|------|------|
| ステータス | 計画承認待ち（**着手は任意**） |
| 依存 | Phase 3 以上が実用になっていること |
| 後続 | なし（以降は個別改善） |
| ゴール | 運用上の必要に応じて、公開・認証・定期実行・要約・Drive を選んで足せる状態にする |

---

## 1. 目的

Phase 1〜4 は「ローカルで無料に回す」が主目的。  
Phase 5 は **必要性が出てから** 選ぶ拡張メニューであり、一括実装しない。

このドキュメントは「何をどういう順で検討するか」のメニュー表として使う。

---

## 2. スコープの考え方

### やること（候補）

| 候補 ID | 内容 | 着手トリガー例 |
|---------|------|----------------|
| P5-A | ホスティング（常時 Web） | 外出先スマホから毎回使いたくなった |
| P5-B | 簡易認証（個人専用） | URL を持つと第三者が触れうる状態になった |
| P5-C | GitHub Actions 定期実行 | 任意トリガーに加え、朝の自動生成が欲しくなった |
| P5-D | 無料枠 AI 要約 | 抜粋だけでは壁打ち前情報が足りないと感じた |
| P5-E | 有料 AI 要約 | 無料枠の品質/制限に不満が出た |
| P5-F | Google Drive 連携 | MD DL 運用が手間になった |

### やらないこと（現時点の方針）

- 最初から全部盛る
- マルチユーザー向け SaaS 化
- 高精度推薦システム

---

## 3. 推奨検討順

必要が出たときの標準順（状況で入れ替え可）:

1. **P5-A + P5-B**（公開するなら認証はセット）
2. **P5-C**（定期実行が欲しい場合）
3. **P5-D → P5-E**（要約）
4. **P5-F**（Drive）

理由: 公開と認証はセキュリティ境界、要約・Drive はコストと複雑性が高い。

---

## 4. 各候補の詳細計画（概要）

### P5-A ホスティング

- 単一プロセス（FastAPI + SQLite）を載せられる先を選ぶ
- SQLite の永続ボリューム要否を先に確認
- bind / 逆プロキシ / HTTPS はプラットフォームに従う
- **完了条件**: スマホのブラウザからログイン前提で一覧と取得ができる

### P5-B 簡易認証

- 候補: 共有パスワード（Basic Auth）、Magic Link、Google OAuth（個人 Google のみ許可）
- 初期は運用コスト最低のもの（Basic Auth or 単一パスワードミドルウェア）で十分な可能性が高い
- **完了条件**: 認証なしでは一覧も取得もできない

### P5-C GitHub Actions

- `workflow_dispatch` + 任意で schedule
- 出力先: Artifacts / リポジトリ内 markdown / Webhook で本番 Web に取り込み、などから選ぶ
- Web 主トリガーは維持し、Actions は副経路
- **完了条件**: 手動/定期で取得結果がどこかに残る

### P5-D 無料枠 AI 要約

- 既存の `excerpt` / `value_line` の後ろに「任意の要約層」を差し込む
- 失敗時はルールベースにフォールバック（必須）
- プロバイダは着手時に再選定（無料枠の情勢が変わりやすい）
- **完了条件**: 要約オンでもオフでもパイプラインが落ちない

### P5-E 有料 AI

- D と同じインターフェースでプロバイダを切替
- 予算上限・1 実行あたりトークン上限を設定化
- **完了条件**: コスト上限を超えたら要約スキップして継続

### P5-F Google Drive

- OAuth またはサービスアカウント（個人運用なら OAuth）
- 出力は Phase 2 Markdown をそのままアップロード
- **完了条件**: 実行後に Drive 上の特定フォルダへ `.md` が置かれる  
- 失敗時はローカル DL にフォールバック

---

## 5. アーキテクチャ上の約束（先に守っておくこと）

Phase 1〜4 で次を守っていれば、Phase 5 の差し込みが楽になる。

- 要約は `Item.excerpt` を上書きするのではなく、`summary` など別フィールド or 出力層で扱う
- 外部連携（Drive / LLM）は Adapter と同様に隔離モジュール
- 認証は Web 層に閉じ、パイプライン純関数に持ち込みない

---

## 6. タスク分解（着手時の型）

Phase 5 は巨大 PR にしない。候補 ID ごとに worktree / PR を分ける。

例:

1. 短い設計メモを `docs/plans/tech-catchup/YYYY-MM-DD-p5a-hosting.md` に追加
2. 実装ブランチ `cursor/phase-05a-hosting-<suffix>`
3. Exit Criteria をそのメモに書く
4. マージ後に運用確認

---

## 7. 完了条件

Phase 5 全体の完了条件は設けない。  
**選んだ候補それぞれの完了条件を満たしたら、その候補は完了。**
